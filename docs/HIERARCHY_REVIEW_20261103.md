# 本次修改审查记录

What this change does:
按用户确认的阶段恢复规则替换全局两次/240步超时/fallback策略，补齐请求追踪、错误分类和成功耗时对照。
审查范围包含控制器、服务端、调用方、测试、日志与报告工具。预期负载为单个评估工作流，共享一个模型服务；未做多租户吞吐设计。

## 审查发现与修复

1. 连接重置后重试身份变化，会让服务器重复进行同一推理。
   已将 ConnectionError 和 HTTPException 纳入通信错误分类，重用请求身份。
   新测试先观察到失败（:1 变成 :2），修复后通过。
2. 模型将 status/caption_type 输出为列表时，集合查询抛 TypeError，导致原始输出丢失并错误归类为服务故障。
   已明确校验枚举类型并抛 ValueError，进入保存原始输出的模型输出错误路径。
   新测试先观察到 TypeError，修复后通过。
3. 耗时比较不能把未实际使用的随机种子当作配对依据。
   动态指令与从状态恢复路径的 seed 标记为空，不用未消费的 ep_seed 伪造配对。
4. 服务端持续运行时不应在内存重复保留全部磁盘事件。
   服务 EventLog 采用不保留内存副本模式；完整事件仍逐条写盘。
